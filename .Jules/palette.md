## 2025-03-01 - Modal Dialog Accessibility & Safe Defaults
**Learning:** Reusable confirmation dialog components often lack critical accessibility attributes (like `role="dialog"`, `aria-modal="true"`, and explicit title/description associations via `aria-labelledby`/`aria-describedby`), significantly degrading screen reader experiences. Furthermore, it's a common UX anti-pattern to leave the default focus undefined or placed on the primary "Confirm" action, which can lead to accidental destructive actions if a user instinctively hits "Enter" immediately upon the dialog appearing.
**Action:** When creating or modifying modal dialogs in this repository, always ensure they are fully annotated with appropriate ARIA dialog properties matching the title and description elements. Always use the `autoFocus` property (or manual focus management) to place the initial focus on the safest default action, typically "Cancel" or "Close", to prevent accidental data loss or unwanted confirmations.
